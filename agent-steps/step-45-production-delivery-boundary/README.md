# Step 45 代码说明：生产交付与上线边界

本步不新增 Agent 能力，复用 Step 41 综合演练版：

```text
agent-steps/step-41-final-rehearsal/backend/
```

这里关注的不是“再加一个功能”，而是把能不能交付说清楚：灰度、回滚、兜底转人工、验收证据和风险清单。

## 本步验证材料

```text
production_delivery_checklist.json
```

你可以把 `production_delivery_checklist.json` 当作交付前自查表，重点看三件事：

- 交付清单里是否包含上线边界、验收证据、回滚和转人工策略。
- Step 41 `/eval/run` 的 15 条显式离线项目回归场景是否仍然全部通过，即 `passed=15`、`failed=0`。
- 再用 `电子发票通常多久能准备好？` 这类 FAQ 问题观察模型调用证据。有模型配置且首次查询的公共缓存未命中时，路由模型和最终话术模型会参与。公共缓存命中时应看到 `common_hit_cache=true` 和 `model_calls.final_answer=0`，但缓存位于路由之后，不能据此推断 `model_calls.route_planner=0`。没有模型配置时，系统要明确走确定性项目回退，而不是伪装成模型成功。

## 没有提前做的能力

- 不创建真实发布平台。
- 不做自动灰度控制器。
- 不接入真实客服工单或告警系统。
- 不承诺 Agent 可以无人值守处理资金动作。
